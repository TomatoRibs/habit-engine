# habit-engine

把「想做但做不到」拆成今天能做的动作。

不是打卡工具，也不是励志内容。它是一套有固定流程的对话协议：先翻旧账找出上一次死在哪，再把愿望剥成一个最小动作，然后铺三层装置（环境／一个人加一笔押金／每天一条记录），四周内按记录调参。

---

## 它解决什么，不解决什么

**解决**：知道自己该做什么，但一直不开始；开始过几次，都断在第 3 天到第 2 周；计划列得很细，执行率是零。

**不解决**：需要临床判断的问题（抑郁、焦虑、ADHD、睡眠障碍、物质依赖）。这类情况它会停下来转介，不给行为方案。也不解决「这份工作每天 12 小时」这种结构问题——那种情况下它能插的只是一根针。

## 怎么用

第一次调用时它会问一句：这件事你试过几次，上一次断在哪。这句是分流用的，不是寒暄——从零、断过、反复断，三条路的做法不一样。

之后是按阶段交付，一段做完再做下一段。**单条消息不超过 250 字**，因为一次给完的结果是一件都不做。

三段分别是：

走完第 0 天，他手上应该有四样：一个具体动作、一个铺好的环境、一个人加一笔押金、一条每天在跑的记录。

| 段 | 改什么 | 交付物 |
|---|--------|--------|
| 第一段 · 铺开 | 改环境和摆法，把动作拆到不用下决心 | 三件当天能做完的小事 + 一张照片 |
| 第二段 · 押注 | 加一个每周会问的人，加一笔真会出去的钱 | 一张转账截图 |
| 第三段 · 追踪 | 每天问一句，节点回头看记录 | 一个自动化的每日问候 |

## 校验

发任何一条消息之前：

```bash
python3 scripts/check_message.py <消息文件>
```

交付或改动这个包之前：

```bash
python3 scripts/check_skill.py          # 17 条规范
python3 scripts/check_skill.py --strict # 警告也算失败
python3 scripts/check_skill.py --list   # 只列规则
```

`check_skill.py` 查的是这个包作为交付物合不合格：frontmatter 完整、name 等于目录名、点名的文件真实存在、编号不跳号、无孤儿文件、版本三处一致、无未完成标记、包内不放运行时数据。

两条最值得说的：

- **S16 旧口径扫描**：`references/` 里出现已被推翻的说法（比如「押一件你真在乎的事」「转他两百」），直接失败。条款改了、执行文件没改，输出就会退回去。
- **S17 条款与示例绑定**：把对话样本里每条消息抽出来逐条跑 `check_message.py`，有一条不过就失败。示例比条款更容易被模仿，示例旧了等于规则没改。

`check_message.py` 查的是某一条消息合不合格：阶段开场有落点、方法论在动作前、动作不超三条、不用 Markdown 符号、动作不串成流程。

两个脚本都不依赖第三方库，只用标准库。

## 运行时数据放哪

**不写进这个包。** 会话状态写到使用者的工作区：

```
<cwd>/.workbuddy/habit-engine-state/YYYY-MM-DD-<场景>.md
```

skill 目录是只读交付物，往里写状态会让包变成脏的。`check_skill.py` 的 S13 会拦。

## 依据

主书三本：《原子习惯》（Clear）、《习惯的力量》（Duhigg）、《认知觉醒》（周岭）。按场景跨书调用《影响力》（Cialdini）、《福格行为模型》（Fogg）、《思考，快与慢》（Kahneman）。

三条硬规矩来自证据分级：

- **A 级**（元分析或大样本实测）可以单独作为依据。
- **B 级**（单一实证）可以配着用。
- **C 级**（仅作者主张）不得单独押注，必须配一条 A 级动作。

这个包里没有独立证据库，所以规则是就地标级：标不出来源的那句话，一律当 C 级处理。

三本书也有各自的盲点，写在 `SKILL.md` 的「诚实边界」里，引用时要能说出来。

## 已知局限

六轮测试全部记录在 `TESTS.md`，包括证明不了什么。

最重要的一条：**机制层从未被真人验证。** 三轮真人对话里，使用者一路在纠正表达方式（方法论怎么写、动作怎么给、话术怎么去 AI 味），没有机会验证这套装置到底有没有让人真的动起来。所以「四周调参」「阻力分」这些机制目前只有设计依据，没有效果数据。

这一点不打算靠文档掩盖。
