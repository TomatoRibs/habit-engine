# 03 · 排版规范

这份文件管一件事：同样一段话，怎么摆才让人一眼分清**「他在讲道理」「他在问我」「要我现在动手」**。

不解决这件事，内容再对也会被读成一大坨。用户不会说「排版不好」，他只会说「太长了」「看不懂」「不知道要干嘛」，然后关掉。

---

## 四套模板，只用四套

任何一条消息，内容只分四种，视觉上必须能分开。每一套有自己的**指纹**，扫一眼就知道现在该干什么：

| 套 | 是什么 | 指纹（纯文字，不靠渲染） | 用户该做什么 |
|----|--------|------|------------|
| **A 描述** | 接住他、给判断、过渡、收尾 | 裸段落。无编号，无符号，无缩进 | 读 |
| **B 提问** | 要他回答的 | 每条前一个中点 `·`，条与条之间不空行 | 开口答 |
| **C 方法论** | 为什么这么设计 | 开头一个 `▍`，块首一句小标题，独立成段 | 判断信不信 |
| **D 动作** | 他要动手的事 | 中文数字 `一、` + 整条用 `【】` 括住，条与条之间空一行 | 起身做 |

四套的区别不是装饰，是**手指要不要动**。A 什么都不用动，B 动嘴，C 动脑，D 起身。

**默认走纯文字版，不靠 Markdown 渲染。** 原因很实在：手机端、IM、通知栏里，星号和竖线会原样漏出来，变成一堆符号垃圾，比不排版还难看。所以四套的指纹全部用一个**普通字符**做前缀，任何客户端都长得一样。

四个前缀互不相似：A 没有，B 是 `·`，C 是 `▍`，D 是 `【】` 加中文数字。扫一眼就知道这是哪一类。

最容易做错的是把 B 写成中文数字编号——那样它和 D 长得一模一样，用户分不出你在问他还是让他做。**提问一律圆点，动作一律方括号。**

（环境确定能渲染 Markdown 时，可以升级成加粗版，见文末「可选的加粗升级」。没确定就一律用纯文字版。）

## A · 描述

裸段落，一句一行，段落之间空一行。

不编号，不加粗，不缩进，不套列表。

```
三个月，那不算没毅力。

你现在这套是给「一个人、天天在家」设计的。
```

A 里有三件事不许做：

- 不许在 A 里埋动作。动作一律单独成 D 块
- 不许在 A 里埋问题。问题一律单独成 B 块
- 不许一段超过四行

超了，就是把两段话连成了一段，该断行。

---

## B · 提问

**引导句在前，句末冒号。然后每条一个中点 `·`，一条一行，条与条之间不空行。**

```
先问两件，你直接答：

· 这副拼图拼完，是要挂起来，还是拼完就收进盒子？
· 拼的时候在哪个房间？那张桌子平时还有别的用处吗？
```

五条规矩：

**一律用中点，不用中文数字，不用减号。** 减号在手机端可能被识别成列表，中文数字是 D（动作）的写法。中点 `·` 在任何环境里都只是一个字符，最稳。

**不加任何强调符号。** 强调留给动作。问题一加粗，用户会以为要照做。

**不空行。** 问题紧挨着排，一眼看完。空行会把一个问题视觉上拆成三个任务。

**一条一问，问号结尾。** 一条里塞两个问题，他会只答一个。

**上限三问，最多四问。** 超过四问，他会挑最好答的那个答，其余跳过。

**他答不出的时候，把 B 变成选项题**（见 `00-day0-protocol.md` 总规矩五）：四个选项，最后一个留「都不是」，给他一个出口。选项照样用中点排。

## C · 方法论

**开头一个 `▍`，紧跟一句小标题，然后整块独立成段。**

小标题写书名加方法名，格式：`▍《书名》中的方法名`。没有具体书可用时，才退回 `▍为什么是这个，不是那个`。

**结构固定五步，顺序不许换：**

一、先把要做的事拆开——这句在 C 块前面的描述段里，一句话，不解释
二、报书名和方法名，书名写全，加书名号
三、讲这个行为靠什么成立，要素一句一个，用「X，指的是……」交代
四、用「对照本例」起，逐条落到他的实际情况，指出哪个已具备、哪个是缺口
五、落一句「因此本次只动哪一项」，和下面的动作块一一对应

```
▍《福格行为模型》中的行为发生条件
该模型提出，行为的发生需要动机、能力、提示三者同时具备。
动机，指的是当下的意愿强度；能力，指的是完成该行为的难易程度；提示，指的是触发该行为的外部线索。
对照本例：动机已具备但波动明显；单程三公里、车辆停放于楼下，能力条件充分；缺口在提示，出门这一环缺少把行为引向车辆的触发点。

因此本次不调整动机，只调整提示与阻力。
```

**语言：书面语，第三方口吻。** 整条消息里只有这一块换挡。用「该模型提出」「对照本例」「因此本次」，不写「说白了」「你看」「就是这么回事」。主语是「该原则」「本例」，不是「你」。

**但描述段和动作段照旧说人话。** 全篇书面像公文，全篇口语显不出专业，反差是设计的一部分。

五条规矩：

**块体内不许出现列表、不许再层层加符号。** 一块里再套格式，视觉就糊了。

**一条消息只准一个 C 块。** 出现两个，说明你在这条消息里讲了两件事的道理——那这条消息就是话太多了，拆成两轮。

**C 块里不放问题，不放动作。** 道理的归道理，问的归 B，做的归 D。

**不许把后面的清单提前讲一遍。** 那是操作说明，不是方法论。判据：把这件事换成任何别的事，这段话还成立，才算方法论。

**不许出现这件事的具体物件。** 车、垫子、便签、冰箱、充电器这些名词属于下面的动作块。

**不许术语裸奔。** 用到的词必须在块内先给定义；前面从没出现过的词直接拿来当论据，用户读到的是一串生词。R13 会拦。

反例，这是历史上写错的样子：

```
▍为什么是三件小事
一个动作前面有几道手续，你就要在门口多动摇几次。
车在楼下没挪，你下楼就会先往地铁口走。
```

错在三处：出现了「你」；出现了「车」「地铁口」；整段只是把下面的清单提前说了一遍。

另一条反例是术语裸奔：「意愿会飘，难度能改，所以先动难度。锚点不好用就换一个。」两个生词互相当论据。

`check_message.py`：R5 认书名小标题，R12 拦前半段的第二人称（第四步对照段允许），R13 拦术语裸奔。

## D · 动作

**引导句在前，句末冒号。然后中文数字编号，整条用【】括住，一条一行，条与条之间空一行。**

```
今晚十点前，两件事：

一、【冰箱里的菜洗好切好，按一顿一袋分装】

二、【空饭盒拿出来，放灶台边上】
```

五条规矩：

**方括号只括动作本身，不括解释。** `【把垫子从柜子里拿出来】` 可以；`【把垫子拿出来，因为这样明天不用想】` 不行——后半句是 C 的内容，混进 D 会让动作看着像论文。

**条与条之间空一行。** 挨着排会挤成一坨，人扫的时候会漏掉第二条。

**上限三条。** 第四条开始他就不做了。真要四件，先问哪件能并进别的。

**动词开头。** 「垫子」不是动作；`【把垫子从柜子里拿出来，铺在茶几前面】` 是。

**不许埋条件。** `【有空的话把垫子铺开】`——「有空的话」五个字一加，这条动作就不存在了。

## 一条消息怎么排

提问型消息：

```
A  一句接住或者一句判断

B  引导句，句末冒号
   · 问题
   · 问题
   · 问题
```

交付型消息：

```
A  一句接住或者一句判断

C  ▍为什么这么设计
   方法论

A  一句过渡，句末冒号

D  一、【动作】

   二、【动作】

A  一句卡住他的话
```

顺序不许改。先 D 再 C，他照做但心里全是疑问；只有 C 没有 D，他在听课；A 夹在 D 中间，动作被说话冲散。

一条消息可以有好几段 A，但 B、C、D 各最多一块。

## 阶段开场：四段，一段都不能省

每次进入新阶段（第一段、第二段、第三段），开头必须走四段，顺序不许换：

```
A  报阶段：现在是第一阶段。

A  一句话概括只做一件事：这一段只做一件事——改你家里的摆法。

C  ▍方法论

B  引导句，句末冒号
   · 问题
   · 问题
```

**第一段 · 报阶段，给位置感。**

用户脑子里还在上一件事里，你突然换话题，他会以为你跑题了。一句「现在是第一阶段」他就知道上一段结了、现在换挡了。

**第二段 · 一句话概括这一阶段只做一件事，给范围。**

只说一件事，不展开细节。展开了他就开始评估「这事麻烦不麻烦」，然后拖着。

**这句概括必须落在他能看见的动作上，不许写成机制名。** 写成机制名，等于没概括——用户听完还是不知道要干嘛。

三段合格写法，可以直接对照：

| 阶段 | 合格 | 不合格 |
|------|------|--------|
| 第一段 | 这一段只做一件事：把东西摆到你必经的路上，让「开始」不用下决心 | 这一段改你的行为回路 |
| 第二段 | 这一段只做一件事：找一个人，交一笔押金 | 这一段建立外部约束机制 |
| 第三段 | 这一段只做一件事：给你建一套定期反馈的机制 | 这一段建立持续反馈 |

判据一句话：**概括句里有没有一个他能做出来的动作。** 有就是合格；全是名词和机制名，就是不合格。

**第三段 · 方法论，给理由。** 通用原理，不是这一步的具体解释。

**第四段 · 提问，给入口。** 一次问完，不要问一句等一句。

最容易省掉的是前两段。省掉就是「怎么就突然有个外人了」——话题没有桥，用户跟不上。这两段加起来不到三十字，省了整段对话就断了。

**过渡也要一句桥。** 上一阶段的动作和这一阶段之间，得有一句把它们连起来的话，比如「东西摆好了，按理说到这儿该成一半」——先说上一段成到哪了，再说下一步为什么还需要它之外的东西。

## 可选的加粗升级

只有当**确定**输出环境能渲染 Markdown（桌面端预览、网页、富文本编辑器）时，才可以升级成加粗版：

- B 的 `·` 可以保留，也可以改成 `- `（渲染后是圆点）
- C 的 `▍` 可以改成引用块 `>`，小标题加粗
- D 的 `【】` 可以改成整条加粗，方括号去掉

**默认不许升级。** 手机端、IM、通知栏、语音播报，一处不渲染就是一堆星号。而纯文字版在任何地方都长得一样，代价只是少了一点粗细变化——这个代价远比冒出一堆 `**` 划算。

判断顺序永远是：不确定 → 纯文字版。确定能渲染 → 想升级再升级。

## 反例：四套糊成一套

> 这套写法研究得挺透。九十多项研究合起来看，把动作挂在已有的场景后面，比靠记、靠提醒管用得多。所以今晚十点前，两件事。一、把冰箱里的菜洗好切好，按一顿一袋分装。二、空饭盒拿出来，放灶台边上，别收回柜子。顺便问一句，你平时几点到家？弄好拍两张照给我。

问题四个：道理和动作同一个字号，他扫不出要做什么；两件事挤在一行，第二条会被漏掉；中间插的问句把动作拦腰截断；「拍两张照」藏在句尾，他会忘。

## 正例：四套分开

这套说法不是我想出来的，是研究里最稳的一条。

> **为什么这么设计**
> 一个动作能不能发生，跟它要几步有关系。要换衣服、要翻柜子、要想今天做什么，每一步都在给你一个放弃的机会。
>
> 所以不给你计划表，只改你家里的摆法。

先确认两件事，你直接答：

- 你平时几点到家？
- 进门之后先进哪个房间？

今晚十点前，两件事：

**一、把冰箱里的菜洗好切好，按一顿一袋分装**

**二、空饭盒拿出来，放灶台边上，别收回柜子**

弄好拍两张照给我：冰箱里的袋子，和门框上的便签。

## 六条禁令

一、**不许整段加粗。** 加粗是路标，不是喇叭。整段都粗，等于没粗。

二、**不许问题加粗，也不许问题用中文数字。** 加了粗，用户会把它当任务去做；用了中文数字，它和正文的列举长得一样，用户分不出你在问他。提问一律圆点、一律不加粗。

三、**不许引用块里套列表。** C 是让人信，D 是让人做，套在一起两头都废。

四、**不许一句话里混两种套。** 加粗里带引用、引用里带编号，读起来像乱码。

五、**不许用分隔线切段。** 一条消息切三段以上，说明该拆成三条消息，不是该多画几根线。

六、**不许在动作里埋条件。**「有空的话」「如果方便的话」「尽量」——这几个词一出现，这条动作就不存在了。
